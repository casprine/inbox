## Known limits
- Snapshot baselines are recorded on iPhone 17 Pro / iOS 26.5 (`make ios-record-snapshots` after an intended UI change).
- After changing a type in one InboxKit module, an incremental build can crash at launch (stale module); delete `~/Library/Developer/Xcode/DerivedData/Inbox-*/Build` and rebuild.
- The app opts out of Liquid Glass (`UIDesignRequiresCompatibility`); if Apple removes that key the toolbar buttons get glass capsules again.
- Our tests use their own simulator (`make ios-sim`) because other projects on this Mac share "iPhone 17 Pro" and steal the foreground (blank snapshots).

## Signing, TestFlight and the server URL (owner steps; nothing here has been done)
1. **Apple Developer Program account** (paid) and an App ID for `com.casprine.inbox`. No special capability is needed (Sign in with Apple was removed, D-012). Local-network access is declared in Info.plist (Bonjour `_alfather._tcp`, usage string); no other capabilities.
2. In `ios/project.yml` set `DEVELOPMENT_TEAM` (currently empty) and remove `CODE_SIGNING_ALLOWED: "NO"` for release builds. There is no entitlements file. Run `make ios-gen`.
3. **Server URL**: the person types it on the sign-in screen (the Tailscale Serve host, e.g. `mini.tail1234.ts.net`) and the app remembers it (UserDefaults `api_base_url`). `InboxAPIBaseURL` in Info.plist is now only a fallback for the signed-out state; leave it empty. https only (ATS allows plain http to local networks). `INBOX_DEV_TOKEN` / `INBOX_API_BASE_URL` environment variables only work in Debug builds and the simulator.
4. On the server set `OWNER_PASSWORD` (see `docs/DEPLOY.md`); the phone needs Tailscale to reach the Serve address.
5. **Archive and upload**: `xcodebuild archive -project ios/Inbox.xcodeproj -scheme Inbox -configuration Release -destination 'generic/platform=iOS' -archivePath build/Inbox.xcarchive INBOX_API_BASE_URL=https://…`, then Xcode Organizer → Distribute App → App Store Connect (TestFlight). Create the app record in App Store Connect first (name, bundle id, privacy questionnaire: the app collects nothing itself; mail stays on the owner's server).
6. **Fonts**: Open Runde (SIL OFL, D-011) is bundled and registered in `UIAppFonts`; mono is the system monospaced font. Credit line in Settings → About; the full licence text is `Inbox/Fonts/OFL.txt`, shown in Settings -> About -> Open Runde.
7. App icon and launch screen are still the defaults (design has not delivered an icon).
8. CI: `docs/handoff/swift-to-backend.md` has the `ios` job (tests + unsigned archive); it has never run on GitHub.

## Server sign-in replaces Sign in with Apple (2026-10-31, D-012)
- **Flow:** Welcome (OB01) only navigates. "Get started" and "I already set this up" open the sign-in screen (OB01b, `FeatureOnboarding/SignInScreen.swift`, model `SignInModel`) in mode `new` / `existing`; mode `signedOut` is opened by the Mail-root banner after a 401 (see Round C below). `POST /v1/auth/login {password, device_name}` goes to the typed address (`APIClient.login`, 15 s timeout); the device token goes to the Keychain, the normalised address to UserDefaults `api_base_url`, the password is dropped. The client switches its base URL after the first successful login.
- **Address rules** (`API/ServerAddress.swift`): https added when missing, host lower-cased, path/query/trailing slash dropped, port kept; http only for localhost, `*.local`, `*.localhost`, loopback and private IPv4 (127/8 added to the spec list so the dev server works).
- **States:** empty, ready, loading, invalid URL (+ public http), wrong password (401 `invalid_credentials`: password cleared, no "tries left" text because the server sends none), locked out (429 `Retry-After`: banner and button count down, kept in memory per server for the launch), unreachable / TLS / 5xx banner with Try again, not an Inbox server, "couldn't save the sign-in" (Keychain failure).
- **Destinations:** new -> OB02. Existing -> the server's `setup_step`, else (field absent) Mail when the server already lists businesses, else OB02 (see Round C below).
- **Removed:** `AppleSigning`, `SystemAppleSigner`, `MockAppleSigner`, `AppleAuthRequest/Response`, `authApple`, the Apple copy, the `/v1/auth/apple` mock. There never was an entitlements file in `project.yml`.
- **Debug aids:** `-OpenSignIn new|existing|signedOut` (mock mode screenshots), `-ResetSignIn 1` (clears token and step, Debug only), `-NoDevToken 1` (ignore a dev token from Local.xcconfig). Mock passwords in `-UseMockData`: `wrong-password`, `locked-out`, `server-down`; anything else signs in.
- **Welcome AX3:** from AX1 the buttons and footer line sit in the scroll content (no longer cut off); "I already set this up" wraps to two centred lines.
- **Fonts:** the sign-in title and welcome h1 use Open Runde Bold (`Font.inboxHeadingBold`). The rest of the D4 §2.3 size/tracking table is not applied app-wide by this change.

## Round C (2026-10-31): signed-out state, setup_step resume, Open Runde licence
- **Signed out (C-20).** `APIClient.perform` sees a 401 on a request that carried a bearer token: it clears that token (only if the store still holds the same one, so a sign-in that finished meanwhile is safe) and calls `onUnauthorized` once. `AppEnvironment.session` (`SessionMonitor`) turns that into `isSignedOut`; the Mail root shows the banner "You've been signed out. Mail on this phone stays readable. [Sign in]" and Sign in opens OB01b in signed-out mode full screen (`SessionSignInScreen`, title "Sign in again", saved address pre-filled, password focused). Success stores the new token, bumps `session.epoch` (restarts the event stream, refetches, flushes the outbox); Back leaves the app signed out. The server address (`api_base_url`) and cached mail are kept. A launch with setup finished, a remembered address and no token (revoked while closed) opens signed out instead of Welcome (`OnboardingState.hasLostSession`).
- **No retry loop.** After the 401 the token is gone, so every later call throws `APIError.notAuthenticated` locally without a request; the event stream treats it (and a 401) as `.unauthorized`, ends and is not restarted until a sign-in; the outbox stops on a session-lost error and keeps its queued ops (it used to drop them as "permanent rejection"). Unit tests count requests: 1 reaches the server, 25 further calls make 0. A wrong password at login is not a session loss.
- **`setup_step` (C-19).** `LoginResponse.setupStep` is optional. "I already set this up" resumes at `done` (Mail), `gmail` (OB05 Gmail) or `domains` (OB02) without extra requests; absent or unknown values keep the old rule (Mail when the server lists businesses, else OB02). "Get started" always goes to OB02. Tested with fixtures both ways; works with or without the backend field.
- **Open Runde licence (C-21).** Settings -> About -> "Open Runde" row opens `LicenceScreen`: the whole `Inbox/Fonts/OFL.txt` (read from the app bundle, fallback sentence if missing), re-flowed into paragraphs (same words, line breaks only; the file is hard-wrapped at 75 columns), selectable, scrolls, scales with Dynamic Type. The one-line credit stays under the About list.
- **Banner:** the shared `Banner` puts its action on its own line from AX1 (as D4 §1.7 specifies for the sign-in banner).
- **Debug aids:** `-SignedOut 1` (mock mode: Mail-root banner), `-OpenSettings licence`.
- Snapshots: `ML01-signed-out`, `ST05-about`, `ST06-licence` (light, dark) and `AX3-` versions.
- **Verified 2026-10-31 (simulator `Inbox iPhone 17 Pro`, one suite at a time):** `make ios-test` 205 pass; `make ios-ui-test` 8 pass; `make ios-e2e` 11 pass against the real dev server (new: revoke a device through `DELETE /v1/devices/{id}` -> banner -> Sign in again with the saved address -> Mail; "I already set this up" follows the server's real `setup_step`, which is `gmail` in the sandbox because it has no Gmail account, so the test skips Gmail and Finish).
- **Not verified:** VoiceOver on the banner and licence screen; a revoked token while an event stream is open (the server may keep an open stream alive after revoke; the app only notices on its next request); licence text selection by hand.
